# Stack

Versions and release dates were read from PyPI, the npm registry and official documentation on 2026-11-11.

| component | choice | version and release date | why | alternative rejected |
|---|---|---|---|---|
| agent framework | LangGraph: one custom `StateGraph` with two nodes (model call, tool call) and no checkpointer, on `ChatAnthropic`; the same graph serves both benchmark arms and the demo | `langgraph` 1.2.20, 2026-11-05; `langchain-anthropic` 1.7.10, 2026-11-04 | Owner's choice: a graph the reader recognises, and the tracing tool attaches to it with one callback. The benchmark calls it without streaming, where `response_metadata` carries the provider's own `usage` dict (uncached input, cache write, cache read, output), `stop_reason` and `model`. Retries are set to 0 and `max_tokens`, effort and thinking are set explicitly, so both arms send the same request and no call is hidden. | Official `anthropic` SDK (2.8.0, 2026-11-10) with a hand-written loop: fewer dependencies and the raw response with no layer in between, but nothing a reader already knows. The prebuilt `create_agent` with `ToolCallLimitMiddleware`: its limit blocks extra calls with error messages rather than ending the run the way the benchmark defines. Claude Agent SDK (`claude-agent-sdk` 0.2.180, 2026-11-09): it runs the Claude Code binary with its own loop and built-in file and shell tools. |
| semantic layer | Own, one file, with a deterministic compiler behind `query(request)` | Own code, no version | The rule that a request may never sum a meter with its ancestor, and that a node total is the node's own meter, is checked at compile time in a file the reader can read in full. This is Approach A of the approved design. | dbt MetricFlow (`dbt-metricflow` 0.15.0, 2026-09-10) came closest. Its `non_additive_dimension` stops a measure from being summed over a dimension, but the documentation defines it for a time dimension with a `min` or `max` window, not for a parent and child tree inside one table, so it cannot express the rule. Cube (1.8.21, 2026-11-09): `hierarchies` are ordered lists of dimensions for drill down, with nothing on additivity. Malloy (0.0.437, 2026-10-30) rejects a sum across a `join_many` relationship, which is a join rule and not a rule within one table. boring-semantic-layer (0.3.19, 2026-11-11): its README does not mention hierarchies. None of the four can express the rule. |
| database | DuckDB, one file, opened read-only | `duckdb` 2.0.0 (LTS), 2026-10-21 | It is embedded, file based and analytical, and its documentation names the settings `run_sql` needs: `duckdb.connect(path, read_only=True)`, then `SET enable_external_access = false` (no `ATTACH` of a file, no `COPY` to or from files, no `read_csv`, `read_parquet` or `read_json`), `SET autoinstall_known_extensions = false`, `SET autoload_known_extensions = false`, `SET max_execution_time = 10000` (milliseconds per query), `SET memory_limit = '2GB'` (added after the security review of 2026-11-12), then `SET lock_configuration = true`. The 5,000-row limit has no setting and is done with `fetchmany(5001)`. Before execution, model-written SQL is parsed with `sqlglot` (30.31.0, 2026-11-10; DuckDB dialect) and refused unless it is exactly one read statement. | DuckDB 1.5.6 (2026-09-28), the previous line: the DuckDB release calendar lists 2.0.0 as the long-term support release, supported until 2027-10-22, and 1.5 as supported only until March 2027. SQLite was not checked: not verified. |
| MCP server | Official MCP Python SDK, `MCPServer` with three `@mcp.tool()` functions, run over stdio with `mcp.run()` | `mcp` 2.3.0, 2026-10-02 | The design needs a local server with three tools that a standard MCP client can launch. In version 2 of the SDK, `mcp.run()` with no arguments starts a stdio server, and the tools call the same `query` function as the agent. | FastMCP (`fastmcp` 4.1.8, 2026-11-10): a separate package that adds features three local tools do not need. The 1.x line of the official SDK (1.30.0, 2026-09-07) still gets releases but is not the current major version. |
| evals | Plain pytest for the offline checks, plus one script in the benchmark module for the paid run; the project's own deterministic scorer | `pytest` 9.2.0, 2026-10-27 | Scoring is an exact comparison of result rows with a reference, and the offline tests must pass without an API key, so a test runner and a script cover it. The paid run reuses the hand-written agent loop and writes the project's own results file. | Inspect AI (`inspect-ai` 0.3.289, 2026-11-10): a task, solver and scorer framework with its own model layer and log format. It would sit between the harness and the API fields the results file records. Whether it exposes cache token counts was not verified. |
| tracing | Saved transcripts as JSON files are the record every score traces to; Langfuse is attached as a LangChain callback only when its keys are in the environment | `langfuse` 5.2.0, 2026-11-05 | Owner's choice. The files work offline with no account, which the offline tests need. Langfuse adds a browsable trace of each run for whoever sets `LANGFUSE_PUBLIC_KEY` and `LANGFUSE_SECRET_KEY`; with no keys the client disables itself (read in its source, not promised by its documentation), and tests set `LANGFUSE_TRACING_ENABLED=false`. | Langfuse as the only record: published numbers would depend on an external service. Self-hosting it: six services (web, worker, PostgreSQL, ClickHouse, Redis, blob storage) for a repository that otherwise needs none. |
| frontend | React and shadcn/ui, one page, built with Vite to static files, in TypeScript | `react` 19.3.1, 2026-10-14; `vite` 8.3.8, 2026-11-11; `shadcn` CLI 4.23.0, 2026-10-27; `tailwindcss` 4.3.5, 2026-11-06; `typescript` 7.0.2, 2026-07-08 | `vite build` writes plain static files. The page fetches the saved answers as JSON files and replays them as a stream with a timer in the browser; from a local clone the same page calls the demo server on localhost for free-text questions. The shadcn/ui documentation gives Vite as an install path. | Next.js (`next` 16.4.6, 2026-11-09): routing and server rendering that a single static page does not use. |
| charts | Recharts, through the shadcn/ui `chart` component | `recharts` 3.10.1, 2026-07-25 | The page needs one line chart for a time series and one bar chart for a breakdown. The shadcn/ui chart component is built on Recharts version 3 and is added with `shadcn add chart`, so nothing else is installed. | Chart.js (`chart.js` 4.6.1, 2026-10-22): a second styling approach next to shadcn/ui and a wrapper to use it from React. |
| hosting | Vercel (Hobby plan), serving the built `frontend/dist` folder as a static site | Hosted service, no version | The hosted demo is a static page that replays saved answers: no server, no API key, no database, no function. A visitor cannot cause a model call, so there is nothing to authenticate or rate-limit. Vercel detects the Vite project in `frontend/` without a configuration file. It is deployed only when the owner says so (owner's decision, 2026-11-12). Free-text questions run from a local clone on a localhost server built with Starlette and uvicorn, which `mcp` 2.3.0 already installs. | GitHub Pages: the first choice in this document until 2026-11-12; it needs the repository to be public and a deploy workflow, and the owner chose Vercel. Cloudflare Workers static assets (Free plan, `wrangler` 4.160.1, 2026-11-11): a third account for the same static files. |
